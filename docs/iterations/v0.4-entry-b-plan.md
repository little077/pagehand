## 3. Tiptap 怎么接

Tiptap 支持自定义节点和 Image 扩展，但这次**不把图片插进编辑器**。

- 工具栏、提示条、附件托盘都放在 `EditorContent` 外面；
- 编辑器只保留文字；
- 发送时把 `text + attachments` 一起提交；
- 以后要在正文引用附件，再做 `attachmentRef` 节点，只存 ID，不存 base64。

## 4. 截屏技术实现

1. 用户点「截屏」；
2. 按钮进入活跃态（成功色/绿色）；
3. 往页面注入 shadow DOM 覆盖层：页面轻微变暗、十字光标、顶部提示「截屏 · 拖动选择区域 · Esc 取消」；
4. `mousedown` 记起点，`mousemove` 画选框和 `宽 × 高`；
5. `mouseup`：大于 12×12 才有效；小于则提示并退出；
6. 覆盖层先移除，再 `chrome.tabs.captureVisibleTab`，避免提示层被截进图；
7. 按 DPR 把 CSS 矩形换算成图片像素，裁剪并缩到最长边 1600px；
8. 生成附件，按钮恢复非活跃。

截图是像素操作：iframe 里的视频、地图、支付页都只是画面的一部分，不需要读 iframe DOM，所以没有 iframe 限制。

### 边界

- 页面不可见 / 受限页：明确报错；
- 页面在截图前跳转：重新量视口或提示重试；
- 覆盖层 Esc / 取消 / 60 秒超时都能退出；
- 隐藏覆盖层后再截图；
- 4K 屏先缩到最长边 1600px。

## 5. 图片如何发给模型

```ts
{ type: 'image', data: '<base64>', mimeType: 'image/jpeg' }
```

pi-ai 会把它转成 OpenAI 的 `image_url` data URL。base64 只是传输编码；模型看到的是图片，按视觉 token 计费。

- 1MP 左右约 1–2k token；
- 3 张约 3–6k；
- 比 4 万字整页文本便宜，但不是免费，所以要限制数量和分辨率。

发送链路：`Composer` → `send.images` → `AgentSession.send(text, images)` → `agent.prompt(text, images)`。

## 12. 存储方案评估：能不能只存文件路径

### 结论

**截图没有现成的文件路径。** `captureVisibleTab` 返回的是内存里的 data URL，不是磁盘文件。想“只存路径、按路径渲染”，必须先把它写到某个文件系统里；这仍然会在本机存一份图片，只是位置从 IndexedDB 换到别处。

### 几种可选方案

| 方案 | 截图能不能用 | 用户上传头像能不能用 | 是否真的省掉本地副本 | 主要问题 |
| --- | --- | --- | --- | --- |
| base64 存 IndexedDB（当前） | 能 | 能 | 否，且多 33% 体积 | 简单、兼容，但大 |
| Blob 存 IndexedDB | 能 | 能 | 否，但小约 25% | 需要 object URL / base64 转换 |
| OPFS（浏览器私有文件系统） | 能 | 能 | 否，仍在浏览器配额里 | 有“路径”语义，但渲染仍要读成 Blob |
| 下载到用户磁盘 + 存 `file://` 路径 | 能，但要先下载 | 能，但要先保存 | 是 | 扩展页不能可靠渲染 `file://`；路径会失效；每次截图都落盘很打扰 |
| File System Access 句柄 | 需要用户每次保存 | 能（用户选择文件） | 是 | Chromium-only；权限要重新确认；文件被移动/删除就断 |
| 远程 URL | 不能 | 能（网络图片） | 是 | 隐私、可用性、离线都不行 |

### 推荐

1. **短期**：把 `attachments.data` 从 base64 换成 `Blob`，仍然放 IndexedDB；渲染用 `URL.createObjectURL`，发给模型前再转 base64。这样能减体积，不改路径语义，最稳。
2. **想要“文件路径”语义**：用 **OPFS** 把图片写成文件，IndexedDB 只存 `{ opfsPath, mimeType, size }`；渲染时 `getFile()` → object URL。它仍然是浏览器本地存储，不是用户磁盘，但能减少 IndexedDB 体积和列表压力。
3. **用户上传头像**：头像很小，直接存 Blob 最省事。真要做到“引用原文件不复制”，只能用 File System Access 句柄：
   - `showOpenFilePicker()` 拿 `FileSystemFileHandle`；
   - 句柄存 IndexedDB；
   - 渲染时 `getFile()`，可能重新请求权限；
   - 仅 Chromium 支持；文件被移动/删除就失效，需要缩略图兜底。
4. **不建议**存任意 `file://` 路径：扩展页渲染不可靠，路径会变，安全边界也不对。

一句话：**截图想“只存路径”必须先落盘；真正可行的“引用用户原文件”只有 File System Access 句柄，而且只适合用户主动选择的文件，不适合截图。**
