## 2. 入口 A 是什么

用户问「这个图表什么趋势」「验证码是什么」「这个页面为什么错位」时，模型在 Agent 循环里**自己决定**调用 `screenshot`。不是前端定时截图，也不是用户点按钮。

工具返回两块内容：

```text
[文字] 视口 1280×720 CSS px，DPR 2，图片 2560×1440 px
[图片] { type: 'image', data: 'base64...', mimeType: 'image/jpeg' }
```

图片作为工具结果进入模型上下文；用户能在运行步骤卡里看到同一张图。

## 3. 模型怎么知道支不支持图片

参考项目的做法是给每个模型一个能力位：

- 自定义模型列表里每个模型有 `image` 布尔值，用户勾选；
- 转成 pi-ai 的 `Model` 时，`input = image ? ['text', 'image'] : ['text']`；
- 输入框用 `resolvedModel.input.includes('image')` 决定是否启用截图按钮。

Pagehand 现在只有一个当前模型，所以等价做法是设置页一个开关：

- 默认关闭；旧配置没有这个字段也按关闭处理；
- 开启后 `toPiModel` 返回 `input: ['text', 'image']`；
- 只有 `input` 包含 `image` 时，pi-ai 的 OpenAI 兼容请求才会把图片编码成 `image_url` 的 data URL；
- 关闭时截图工具直接返回「当前模型没有开启图片输入」，不会截了图再被请求层静默丢掉；
- 如果用户开了开关、端点仍然拒绝图片，最终错误里会追加「关闭开关或换一个支持视觉的模型」的提示。

这是诚实的能力协商：框架负责编码，是否多模态由用户和端点决定，不靠猜模型名。

## 4. 技术方案

### 4.1 截图 API

`chrome.tabs.captureVisibleTab(windowId, { format: 'jpeg', quality: 80 })`。

- 只截当前可见区域，不滚动、不拼整页；
- 目标窗口取当前活动标签页所在窗口；
- Pagehand 已有 `activeTab`、`scripting` 和 `<all_urls>`，不需要新增 manifest 权限。

### 4.2 元素裁剪

传 `selector` 时：

1. 往页面注入自包含函数，量元素的 `getBoundingClientRect()`；
2. **不滚动页面**；元素完全不在视口内就直接报错「先滚动到它可见」；
3. 元素部分在视口内时，裁剪框夹到可见部分，并标记 `clipped`；
4. 把 CSS 像素矩形按 DPR 换算成图片像素，夹在图片范围内；
5. 在离屏页面用 Canvas 裁剪，返回 JPEG data URL。

不做滚动是刻意选择：截图不应该偷偷改变用户页面位置；后续写操作能力成熟后，可以由 `act` 明确滚动。

### 4.3 工具结果

```ts
{
  content: [
    { type: 'text', text: '截图范围、视口、DPR、图片尺寸、坐标提醒' },
    { type: 'image', data: base64, mimeType: 'image/jpeg' },
  ],
  details: { source, selector, viewport_width, viewport_height, dpr, image_width, image_height, clipped, bytes },
}
```

文字里明确写「图片像素 = CSS 像素 × DPR」，为后续按图片坐标点击做准备。

### 4.4 UI 图片传递

`tool_end` 和 `ChatItem` 的工具项新增可选 `images`；会话从工具结果 content 里提取图片（最多 2 张），运行步骤展开后显示截图。模型上下文仍使用原始 content，UI 只是镜像。

### 4.5 能力与错误边界

| 情况 | 行为 |
| --- | --- |
| 模型未开启图片 | 工具直接报错，附设置指引；不截图 |
| 元素选择器不存在/语法错误 | 明确报错，提示先用 `inspect` |
| 元素尺寸为 0 | 报错「可能还没渲染出来」 |
| 元素不在视口 | 报错「先滚动到它可见」；不偷偷滚动 |
| 截图 API 失败 | 报错并保留原因 |
| 裁剪失败 | 报错并保留原因 |
| 端点拒绝图片 | 最终错误追加「关闭开关或换视觉模型」的提示 |

## 5. 前端表现

- **设置页**：模型下拉下方新增「该模型支持图片输入」复选框；默认关闭。
- **运行步骤**：新增「截图」步骤，图标为相机，摘要显示「已截图当前视口 · 2560×1440」或「已截图元素「#chart」 · …」；展开后显示参数、元数据和图片。

## 6. 用户场景

1. 「这个图表的趋势怎么样」→ 模型截图后直接看图回答，而不是只读坐标轴文字。
2. 「验证码是什么」→ 截图读取图片内容。
3. 「海报上写的什么」→ 图片文字。
4. 「页面为什么错位了」→ 看渲染后的布局、遮挡和溢出。
5. 「把这个图表单独截出来」→ 模型用 `inspect` 找到 selector，再 `screenshot({ selector })`。

## 9. 已知边界

- 只截当前视口；不滚动、不拼接整页。
- 只截当前活动标签页；跨标签页截图留到写操作/多标签能力时。
- 不做 OCR；图片文字由视觉模型自己读。
- 图片会跟随会话写入 IndexedDB；目前一张截图通常几百 KB，后续需要加更严格的配额和清理策略。
- 截图可能包含敏感信息，只发给用户自己配置的模型端点，不写日志、不进 trace。
