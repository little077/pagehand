## 1. 本次迭代做了什么

新增写操作工具 `interact`，并把 `inspect` 的编号升级成页面内稳定 ref。现在 Agent 的闭环从「读、找」延伸到「点、填、等、确认结果」。

| 类型 | 文件 | 说明 |
| --- | --- | --- |
| 页面 ref | `lib/page/ref-store.ts`、`lib/page/inspect.ts` | 隔离世界里的元素→ref 注册表；同一个元素在多次 inspect 中保持同一个 ref |
| 页面动作 | `lib/page/interact.ts` | 自包含注入函数：定位、检查、激活、观测；另有取消等待的注入函数 |
| 工具层 | `lib/tools/interact.ts` | 参数、活动标签页、同标签页串行队列、probe/act 两阶段、导航/新标签页监听 |
| 格式化 | `lib/tools/interact-format.ts` | 给模型的摘要、错误下一步、给 UI 的 details |
| 安全 | `lib/agent/action-safety.ts`、`lib/agent/permission-gate.ts` | 高风险词判断；首次写操作按站点授权 |
| 提示词 | `lib/agent/prompt.ts` | 工具清单、操作纪律、能力边界 |
| UI | `lib/runs.ts`、`entrypoints/sidepanel/lib/runs.ts`、`AgentRun.tsx` | 操作步骤、图标、摘要 |
| 测试 | `tests/page/interact/`、`tests/tools/interact/`、`tests/agent/action-safety.test.ts`、`tests/permission-gate.test.ts` | 动作、检查、等待、序列化、安全、门禁、格式化 |

## 2. 工具能力

`interact` 是一个工具 + action 枚举，不是十个工具：

| action | 用途 | 关键限制 |
| --- | --- | --- |
| `click` | 点击按钮、链接、选项 | 执行前检查可见、稳定、遮挡、禁用、inert |
| `fill` | 替换输入框/文本域/可编辑区域 | 拒绝密码、验证码、银行卡、文件、隐藏字段 |
| `type` | 在现有内容末尾追加 | 不逐字符模拟键盘；用于联想或补充 |
| `press` | 控制键和快捷键 | 不触发浏览器默认的 Tab/回车提交；文字用 fill/type |
| `select` | 原生 `<select>` | 自定义下拉用 click 展开后再点选项 |
| `check` / `uncheck` | 复选框、单选框、开关 | 已经是目标状态时不重复点击；单选框不能取消 |
| `hover` | 触发 JS 悬停逻辑 | 合成事件不会触发 CSS `:hover` |
| `scroll` | 页面或可滚动容器 | 使用 instant，不用平滑滚动 |
| `wait_for` | 等元素出现/消失、文字、值、URL | 1～30 秒，可被用户停止 |

目标定位顺序：

1. `ref`：来自 `inspect`，页面内稳定编号；
2. `selector`：必须恰好匹配一个元素；
3. `x/y`：只允许 click/hover，给 Canvas/地图兜底。

## 3. 执行流程

```text
interact
  → 站点授权门禁（首次写操作）
  → probe：定位 + 检查，不操作
  → 高风险判断（点击/按键/选择/勾选）
  → 用户确认（每次，无“始终允许”）
  → act：重新定位 + 再检查 + 激活
  → 同时监听导航/新标签页
  → 动作后观测 1.2 秒
  → 结构化结果（changed / 错误码 / 下一步）
```

probe 和 act 分开，是为了在真正动手前拿到目标标签，让高风险确认能说清「要点哪个按钮」，同时避免在确认前就执行动作。

## 4. 技术方案

### 4.1 稳定 ref

`inspect` 和 `interact` 是两个独立注入的函数，不能共享模块变量，所以约定同一个隔离世界全局 key：

- `WeakMap<Element, ref>`：同一个 DOM 元素重复 inspect 时复用编号；
- `Map<ref, WeakRef<Element>>`：按 ref 取元素，不重新查询选择器；
- `meta`：保存 selector / role / label，用于错误说明和结果摘要；
- 元素移除或页面导航后，隔离世界销毁，ref 自然失效；
- 元素还在但已脱离文档时返回 `ref_stale`，提示重新 inspect。

好处：列表重排、React 重渲染后不会因为选择器指向别人而误点；模型也不用复制长 selector。

### 4.2 执行前检查

| 检查 | 失败码 |
| --- | --- |
| ref 是否存在、是否还在文档里 | `ref_missing` / `ref_stale` |
| selector 语法、0 个、多个 | `selector_invalid` / `not_found` / `ambiguous` |
| 可见性（display/visibility/opacity/尺寸/祖先隐藏） | `not_visible` |
| 位置稳定（连续两帧矩形不变） | `not_stable` |
| 点击点是否被别的元素接走 | `covered` |
| disabled / aria-disabled | `disabled` |
| 在 `[inert]` 子树里 | `inert` |
| pointer-events:none | `pointer_events_none` |
| 可编辑、只读、输入类型 | `not_editable` / `unsupported_input` |
| 原生下拉 / 勾选控件 | `not_select` / `not_checkable` |

检查失败不会“硬点”，而是返回原因和下一步。遮挡错误会说明覆盖者是谁，例如「被『登录遮罩』挡住」。

### 4.3 激活语义

点击：

1. 滚动到视口中央；
2. 等矩形稳定；
3. 命中测试；
4. 聚焦；
5. `pointerover/enter/move` + `pointerdown/mousedown` + `pointerup/mouseup`；
6. 调用元素原生 `click()` 执行激活行为。

填充：

- 原生 prototype setter 写 `value`，绕过 React 的 value tracker；
- 派发 `InputEvent('input')` 和 `change`；
- contenteditable 用 `execCommand('insertText')`，失败时回退直接写入并提示编辑器状态可能不同步；
- 写入后 50ms 回读，值没变返回 `value_not_set`，被页面改写则提示不一致。

按键：

- 同时填 `key`、`code`，并用 `defineProperty` 补 `keyCode`/`which`，兼容老页面；
- 合成键盘事件不会执行浏览器默认行为，所以 Tab/方向键/原生回车提交都会明确提示；
- 提交原生表单请点击提交按钮。

### 4.4 动作后观测

动作前安装 MutationObserver，记录目标状态（值、勾选、下拉索引）和 URL。

动作后最多观察 1.2 秒，满足任一条件就结束：

- URL 变化；
- 目标从文档移除；
- 目标状态变化；
- DOM 有变更并安静 150ms；
- 超时。

返回 `changed`、`mutated`、最终状态和一句人话。没有变化时明确说「操作已发出，但 1.2 秒内没有看到页面变化」，并提醒先 inspect，不自动重复点击。

### 4.5 导航与新标签页

- 点击可能在注入函数返回前就销毁页面上下文；
- 工具层同时监听 `tabs.onUpdated` / `tabs.onCreated`，导航或新标签页一发生就结束等待；
- 原标签页跳转时等 `status=complete`（10 秒），返回新 URL/标题，并提示旧 ref 失效；
- 新标签页只报告 id/URL/标题，不自动切过去继续操作；
- 导航超时返回成功但带警告，因为动作已经发出，不能假装没发生。

### 4.6 安全

- **按站点授权**：第一次在某个 origin 上做写操作时询问，授权后该站点连续操作；`scroll` / `wait_for` 不询问；
- **高风险每次确认**：支付、购买、下单、转账、删除、注销、发布、发送、提交表单、授权、重置等，即使站点已授权也每次弹确认，没有「始终允许」；
- 表单提交默认也算高风险；搜索框回车和搜索按钮例外，避免每次搜索都弹卡；
- 坐标点到按钮内部 span 时，会向上找最近的可操作祖先做风险判断，不能靠点内层元素绕过高风险；
- **敏感字段硬拒绝**：密码、验证码、银行卡、文件上传、验证码区域；inspect 也不再回传银行卡/验证码的值；
- **只操作当前活动标签页**：开始前、确认后、真正执行前都会重新确认标签页没有切换，也不会对后台标签页静默点击；
- 页面在检查和执行之间跳转、或标签页在执行中被关闭，都会作为明确结果返回，不继续在错误页面上操作；
- **同源 iframe**：跨域 iframe 直接拒绝；
- **提示注入**：网页文字只当数据；系统提示明确不执行页面里的“请点击/忽略以上指令”。

### 4.7 并发、超时与取消

- 同一标签页的 interact 串行执行，避免并行工具调用同时改 DOM；
- probe 硬超时 8 秒；`wait_for` 按用户超时加 2 秒；
- 导航等待 10 秒；
- 用户点停止后，取消等待注入函数并返回 `aborted`；如果动作已经发出，会如实说明“可能已经发出，请检查页面”；
- 页面 `alert/confirm` 阻塞时返回 `page_busy`，请用户手动处理，不覆盖页面弹窗。

## 5. 前端表现

- 运行步骤新增「操作页面」，摘要如「已点击按钮「搜索」」「已填写「关键词」」「已跳转：结果页」「打开了新标签页」「页面无可见变化」；
- 展开后能看到参数和结构化结果；
- 首次写操作弹站点授权卡片；
- 高风险动作弹单独确认卡片，不提供「始终允许」；
- 没有新增独立面板，不改变现有输入框和消息结构。

## 6. 用户场景

1. 「在小红书搜索机械键盘，列出前 5 条标题」→ 填搜索框、回车/点搜索、重新 inspect、读结果。
2. 「把这段反馈填进表单，提交前给我看」→ fill 多个字段，提交按钮触发高风险确认。
3. 「展开评论区，把前十条读给我」→ click 展开、scroll 触发加载、read_page。
4. 「勾选这三条，导出」→ check 三条，点击导出（高风险确认）。
5. 「在地图上点这个位置」→ 坐标点击兜底。

## 9. 已知边界

- 合成事件 `isTrusted=false`，强校验站点可能拒绝；
- CSS `:hover`、原生 select 弹层、浏览器默认 Tab/回车提交不生效；
- 无逐字符输入，富文本联想可能不触发；
- 无返回/前进/刷新动作，进入详情后需要用户手动返回；
- 不支持跨域 iframe、shadow DOM；
- 不自动处理原生 `alert/confirm`；
- 高风险词表可能误判，宁可多一次确认；
- 不绕过验证码、支付风控、登录验证。
