## 1. 本次迭代做了什么

真实页面验收时，用户问「页面输入框在哪、placeholder 是什么」，Agent 连续调用了 7 次工具（5 次 inspect + 2 次 read_page），最后靠读 HTML 才拿到 placeholder。这个过程不是程序错误，但暴露了三个产品缺陷：返回信息不够、没有检索纪律、重复调用无人拦。

本次按 P0 → P1 修复：

| 优先级 | 改动 | 落点 |

| P0 | 元素记录补 `placeholder`、`input_type`、`name`、`autocomplete`、`label_source` | `lib/page/inspect.ts` |

| P0 | 新增 `role` / `kind` / `input_type` 筛选参数 | 工具参数 + 采集器 |

| P1 | 重复调用护栏：连续相同参数 + 页面指纹相同 → 直接复用上次结果 | `lib/tools/inspect-cache.ts` + 工具层 |
| P1 | 步骤摘要识别「与上次检查相同」 | `lib/agent/session.ts` |

## 2. 起因：7 次调用到底在干什么

从截图摘要还原（展开卡片可看到真实参数）：

1. 全页扫描：191 个元素，62 个不可见，默认只返回 40 个；
2. 换选择器缩小范围，命中 1 个隐藏元素；
3. 读 HTML，拿到 0 字；
4. 又试一次，结果和第 2 次相同；
5. 再换范围，0 个；
6. 读 HTML，拿到 420 字；
7. 在目标区域找到 4 个元素，定位到搜索框。

根因不是「页面没变却重复读」，而是：

- 第一次只看到 40/191，模型不知道目标在不在这 40 个里；
- 没有「按类型查」的能力，找输入框只能猜选择器；
- `label` 把 placeholder 当兜底，轮换热搜词「杭州百丈岭」看起来像字段名；
- 提示词没有次数预算，模型倾向于反复确认；
- 两次参数相同的结果无人拦截。

最终答案正确，但 7 次工具调用已经把 8 回合预算用满。

## 3. 技术方案

### 3.1 元素记录新增字段

| 字段 | 作用 |
| --- | --- |
| `placeholder` | 输入框的提示文字，和名称分开返回，不再冒充字段名 |
| `input_type` | `search` / `email` / `tel` / `text` 等，用于精确筛选 |
| `name` | 表单字段名，填表时有用 |
| `autocomplete` | 浏览器自动填充提示 |
| `label_source` | 名称来源：`aria-labelledby` / `aria-label` / `label` / `placeholder` / `alt` / `title` / `text` |

模型看到 `label_source=placeholder` 时，能明确知道「这个名字其实是提示文字」，不需要再读 HTML 确认。

### 3.2 角色统计与截断说明

首次结果增加两行信息：

```
匹配到 191 个可操作元素 · 返回 40 个 · 62 个不可见 · 4 个被遮挡
按类型：link 80（可见 70）· button 60 · textbox 12（可见 8）· combobox 2
```

模型据此可以直接选择下一次的筛选条件，而不是盲猜选择器。

### 3.3 筛选参数

| 参数 | 用法 |
| --- | --- |
| `kind` | `input` / `button` / `link`，按大类过滤；找输入框首选 |
| `role` | 精确角色：`textbox`、`searchbox`、`button`、`link`、`checkbox`、`combobox` 等 |
| `input_type` | 精确 input 类型：`search`、`email`、`tel`、`text` |

可以组合使用，例如 `{ kind: "input", text: "邮箱" }`。条件没有命中时，结果会说明「范围内共有 N 个元素」，并提示去掉哪个条件重试。

### 3.4 编号稳定性

编号现在按「检查范围内的全部候选」的文档顺序分配，`text` / `role` / `kind` / `input_type` 只过滤展示，不改变编号。例如范围内有两个按钮，只筛第二个，它仍然是 `e2`。

这样后续写操作工具只需要复现「范围 + 编号」，不必复现所有筛选条件，降低解析出错概率。

### 3.5 重复调用护栏

- 缓存键 = 标签页 + 全部参数（含新增筛选参数）。
- 页面指纹 = URL + 候选元素的编号、选择器、角色、名称、placeholder、可见性、遮挡状态的哈希。
- 连续两次键相同、指纹相同、间隔不超过 30 秒 → 不再返回完整列表，而是提示：
  「这次检查与上一次完全相同，页面没有变化。请直接使用上一次的结果，不要重复调用 inspect。」
- 页面真的变化（指纹不同）时正常返回新结果，不会误判。
- 只缓存成功结果；选择器语法错误不进入缓存。

实现是纯函数 `shouldReuseInspect()` + 工具层一个按标签页的短缓存，便于单测。

### 3.6 提示词纪律

系统提示的第 7 条现在明确要求：

- 找输入框先传 `kind="input"` 或 `role="textbox"`，找搜索框传 `input_type="search"`；
- 结果里已有 placeholder、input_type、name，不要再去读 HTML；
- 同一目标最多连续查 2 次，第二次必须换更精确的条件；
- 两次都找不到就改用 `read_page`，或直接告诉用户页面上没有该元素；
- 工具提示「与上一次完全相同」时，直接使用上次结果。

## 4. 前端表现

有，但仍然是现有步骤卡的增量：

- 卡片标题、图标、状态不变；
- 摘要仍显示「找到 N 个可操作元素 · M 个不可见」；
- 重复调用被拦截时，摘要显示「与上次检查相同，页面没有变化」；
- 展开详情新增 `scope_total`、`role_counts`、`cached` 字段，便于复盘；
- 没有新增面板、没有页面高亮。

## 5. 用户场景

1. 「输入框在哪」→ `kind="input"` 一次拿到所有输入框，结果直接带 placeholder 和 input type。
2. 「搜索框的 placeholder 是什么」→ `input_type="search"`，一次返回 placeholder，不再读 HTML。
3. 「为什么这个按钮点不动」→ `kind="button"` + `include_hidden=true`，看到隐藏/遮挡/鼠标穿透原因。
4. 「只看弹窗里的按钮」→ `selector="#modal"` + `kind="button"`。
5. 模型重复相同查询 → 第 2 次直接收到「页面没有变化」，避免继续空转。
