# Pagehand Agent 迭代路线

> 更新于 2026-11-09。本文是 README「路线图」的详细拆解：每个阶段做什么、为什么、怎么验收。
> 产品思路参考同类浏览器 Agent 产品的分层与交互，不复制任何项目的代码。

## 1. 现在在哪

已完成：

- WXT + React 19 + pi-agent-core / pi-ai，BYOK，流式对话
- 四个只读工具：`read_page`、`list_tabs`、`read_tab`、`read_selection`
- 单轮最多 8 个回合（`lib/agent/session.ts`），够跑「列标签 → 读多页 → 回答」
- 步骤时间线：序号、状态、耗时、可折叠详情
- 会话落盘 + 多会话列表（本机 IndexedDB，标题三段式）
- 侧边栏与后台的 Port 通信、心跳、断线重连
- Biome + husky + Vitest + CI

主要缺口：

- 没有执行前授权与主动提问
- 没有上下文压缩、Skill / MCP / 记忆
- 网页读取仍依赖最宽的 `<all_urls>`，尚未按站点收窄
- 历史没有导出 / 清理入口

一句话：差距不在模型，在循环、状态和边界。

## 2. 参照：成熟浏览器 Agent 的能力地图

| 层 | 需要的能力 | Pagehand 的落点 |
| --- | --- | --- |
| 读 | 当前页正文、选中文本、跨标签页定位与读取 | `read_page`、`read_selection`、`list_tabs`、`read_tab` |
| 动手 | 列可交互元素、点击 / 填写 / 滚动、执行 JS、标签页管理 | 未开始；阶段 4 做最小闭环 |
| 循环 | 多工具多轮、主动停下问用户、回合上限、取消 | 回合上限已到 8；提问在阶段 3 |
| 权限 | 执行前确认，四种结局：仅本次 / 始终 / 拒绝 / 未回应；按工具和站点授权 | 未开始，阶段 3 |
| 上下文 | 会话落盘、断线续看的流式副本、按窗口比例压缩、token 估算、自动标题 | 落盘与多会话已到（阶段 2）；压缩在阶段 5 |
| 扩展 | Skill 工作流、MCP 外部工具、跨会话记忆、Prompt 模板变量 | 未开始，阶段 6 |

这类产品的共同判断值得记住：**先让 Agent 能读、能问、有边界，再让它动手**。写操作是信任分水岭，不是功能清单里的一项。

## 3. 迭代原则

1. 先只读，后写操作。
2. 先扩循环，再落盘：消息结构稳定后再做持久化，避免存两遍。
3. 每阶段一个可演示场景，加可自动化验收。
4. 新能力默认最小权限；写操作必须经过确认。
5. 不为了「对标」而堆功能。

## 4. 六个阶段

### 阶段 1：三个只读工具 + 步骤时间线（已完成 2026-11-08）

目标：让 Agent 知道「用户开了哪些页面、另一个页面写了什么、用户正指着什么」，并且每一步可见。

状态：三个工具、8 回合上限、步骤时间线均已落地，`pnpm check` 通过。真机加载扩展后的验收场景仍待做。

#### 1.1 `list_tabs`

做什么：列出当前窗口的标签页 `id`、标题、URL、是否活动页。

场景：

- 用户开了三篇评测、一个商品页，问「把三篇评测的结论对比一下」——先列标签，找到三篇的 id。
- 用户说「接着刚才那个页面说」——从标题 / URL 认出目标标签。
- 发现目标页已经开着，直接读，不再重复开标签。

不做什么：不读正文、不切换标签、不关闭标签。

#### 1.2 `read_selection`

做什么：读取用户当前选中的文本，附带页面标题和 URL。

场景：

- 选中一段合同条款，问「这条有什么风险」。
- 选中一段报错信息，问「这个错怎么修」。
- 选中英文段落，问「翻译并解释」。

边界：没有选中内容时返回空结果并提示「先选中文字」，不要抛错。只注入当前活动标签，不碰其他页面。

#### 1.3 `read_tab`

做什么：按 `tabId` 读取指定标签页的正文，复用 `read_page` 的正文抽取逻辑。

场景：

- 两个商品详情页比价，不打断用户当前正在看的页面。
- 读取后台标签里的文档页，读完再回到原页面继续工作。

边界：浏览器可能已经休眠后台标签，需要先激活或重新加载；受限页面（`chrome://`、扩展页）直接返回可行动的错误。

#### 1.4 步骤时间线

连续的工具调用按顺序展示：当前步转圈，历史步折叠，每步显示工具名、耗时和一句结果摘要。

Pagehand 的消息模型已经是 user / assistant / tool 三类（`lib/ipc/protocol.ts`），工具卡天然按顺序排列。现在每条 `tool` 消息带 `startedAt` / `durationMs`，UI 按用户回合编号并显示实时耗时，不需要重做消息结构。

#### 1.5 权限与清单

当前基线已经为读取网页内容声明了 `host_permissions: ['<all_urls>']`，所以阶段 1 的三个工具不需要新增权限。接下来要做的是**收窄**，不是继续扩大：

- `list_tabs` 只需要标签页的标题 / URL，现有 host 权限已覆盖；不读正文。
- `read_tab` 读后台标签页正文同样依赖 host 权限；受限页面（`chrome://`、扩展商店、PDF）直接返回可行动的错误。
- `read_selection` 只在当前活动标签页执行，不碰其他页面。
- 后续单独开一个权限阶段，把 `<all_urls>` 收窄为 `optional_host_permissions` 按站点申请。运行时申请需要用户手势，不能混在工具开发里顺手做。

#### 技术清单

- `lib/tools/list-tabs.ts`：`browser.tabs.query({ currentWindow: true })`，过滤掉浏览器内部页。
- `lib/tools/read-selection.ts`：注入 `window.getSelection()`，兼容输入框 / 文本域的选区。
- `lib/tools/read-tab.ts`：复用 `lib/page/snapshot.ts`，按 `tabId` 注入抽取。
- `lib/tools/format.ts`：给模型看的标签页 / 选中文本格式化，纯函数可单测。
- `lib/tools/index.ts`：注册四个工具并同步白名单。
- `lib/agent/session.ts`：`MAX_TURNS` 从 4 提到 8；按 `toolCallId` 匹配结果，记录耗时与摘要。
- `entrypoints/sidepanel/components/ToolCard.tsx`：序号、实时耗时、折叠详情。
- 测试：空标签页、无选中内容、格式化与截断提示。

#### 验收（真机待做）

1. 开三篇文章，问「我现在开了哪些页面」→ 全部列出。
2. 选中一段英文问「翻译」→ 拿到选中原文并翻译。
3. 在 A 页问「和 B 页对比」→ 找到 B，授权后读取，回答引用两页内容。
4. UI 依次出现三步，运行中有状态，结束后可展开详情。

学习点：工具描述怎么写模型才会选对、工具结果怎么回灌、失败怎么表达。

### 阶段 2：会话持久化 + 多会话（已完成 2026-11-09）

为什么放在阶段 1 之后：多工具会改变消息结构，先定结构再落盘，避免返工。

存什么（`lib/sessions/record.ts`）：

- `id`、`createdAt`、`updatedAt`、`items`（给 UI 的视图）、`messages`（给模型的上下文，去掉开头的 system 消息）
- `model` 只记 presetId / baseUrl / modelId，**不记 API Key**
- `title` 三个来源分开存，展示按优先级取：
  - `custom`：用户改过的名字，一旦有值永久优先
  - `ai`：模型总结的标题，留待设置里接入总结能力后写入
  - `fromPrompt`：首条任务的前 20 个字（按码点切，emoji 不会被切坏），兜底

怎么存：原生 IndexedDB（`lib/sessions/store.ts`，库名 `pagehand-sessions`），没有引入 Dexie。当前会话 id 记在 `chrome.storage.local`，Service Worker 被回收后重开侧边栏能接着看。

什么时候写：新建会话不落盘，等第一条任务发出、且这段跑完（每条回答结束、每个工具结束、整轮结束）才写。列表里不会有空会话，也不会存下半条流式消息。改名不刷新 `updatedAt`，否则只是改个名字就把会话顶到最前。

怎么恢复：历史消息回填时，system 消息用新建 Agent 现算的那条，所以工具清单和系统提示永远跟当前代码一致，不会带着旧的走。

UI：Header 的历史图标打开列表；支持打开、重命名、删除（二次确认，删掉当前会话就回到新会话状态）。列表按 `updatedAt` 倒序，只显示摘要，正文留在 IndexedDB。

验收：关侧边栏、刷新页面、重启浏览器三种情况历史都在；点旧会话能继续追问并引用前文。

风险：消息必须可序列化；工具 `details` 只给 UI，不进模型上下文。

状态：IndexedDB 读写、列表排序、三种标题来源、改名回退、删除与指针清理已在真实浏览器验证；真机加载扩展后「继续追问并引用前文」还没跑。

### 阶段 3：权限门禁 + `ask_user`

为什么：为写操作铺路，也让 Agent 学会「不知道就问」。

- 把 `beforeToolCall` 的白名单扩展为门禁：按工具 + 站点判断，决策分四种：仅本次、始终、拒绝、未回应。
- 「始终允许」只对当前站点 + 当前工具生效，授权落本地。
- `ask_user`：多问题、单选 / 多选 / 自由文本；Agent 信息不足时停下来问，而不是猜。
- UI：权限和提问共用一个「待你处理」卡片区，不另开弹窗。

验收：未授权的写工具被拦住；拒绝后模型收到明确原因；Agent 会先问「处理哪几个标签」再动手。

### 阶段 4：写操作 `inspect` / `click` / `fill` / `scroll`

为什么放这么后：写操作改变「谁对页面负责」，信任和调试成本都高一个量级。

- `inspect` 返回带编号的可交互元素；编号映射放在内容脚本内存，页面导航后作废并要求重新 inspect。
- `click` / `fill` 按编号操作，**不让模型自己编 CSS 选择器**。
- 每次操作后回读页面确认结果；失败区分元素消失、不可见、被遮挡、页面跳转。
- 全部走阶段 3 的权限门禁。

验收：在搜索框输入并提交；填写一个表单；每步有确认，失败能说明原因。

### 阶段 5：上下文治理

为什么：多工具后上下文涨得很快，不压缩会变慢、变贵甚至超限。

- 用字符数近似 token（中文约 1 字 1 个，英文约 4 字符 1 个），不必上 tokenizer。
- 达到模型窗口一定比例后触发摘要，保留最近一段原文；按窗口百分比保留最近 20%，下限 8000 token。
- UI 明示「已将早先 N 条压缩为摘要」。

验收：连续 30 轮后仍能引用早期结论，不出现超限报错。

### 阶段 6：Skill / 模板 / 导出

为什么：从「每次重新说」变成「可复用工作流」，也是开源项目能积累生态的地方。

- Skill：Markdown + frontmatter（`name` / `description` / 触发词），`/` 唤起。
- 变量插值：`{{page_url}}`、`{{selected_text}}`、`{{clipboard}}`。
- 导出：会话导出 Markdown / JSON。
- 之后：MCP、跨会话记忆、定时任务、操作录制。

## 5. 暂不做

| 功能 | 原因 |
| --- | --- |
| MCP | 协议、UI、权限三块都重，先把内置工具打磨好 |
| 跨会话记忆 | 先把单次任务做好，避免记住错误偏好 |
| 多 Agent / 规划器 | 单 Agent + 工具循环足够覆盖浏览器任务 |
| 全站 `<all_urls>` | 按站点按需申请，安装时保持低权限 |
| 定时 / 录制 | 差异化能力，但依赖前面的闭环稳定 |

## 6. 前端落点

- **渲染性能**：已完成消息 `React.memo`，只让最后一条流式消息重渲染。现在每个 delta 都会重渲染整棵 Markdown 树。
- **工具时间线**：序号 + 状态 + 耗时 + 可折叠详情；连续多个工具默认折叠成「执行了 N 步」，展开当前步。
- **待处理卡片**：权限和 `ask_user` 共用，不另开弹窗。
- **会话列表**：抽屉 + 自动标题 + 空状态。
- **错误态**：工具失败显示原因和重试，不只显示「未完成」。

## 7. 每阶段的完成定义

- 代码：新工具单测、`pnpm check` 全绿。
- 真机：加载 `.output/chrome-mv3`，用真实 API Key 跑通验收场景。
- 文档：README 路线图状态更新。
- 安全：权限变更单独写进 README 的安全与隐私段。

## 附录：能力分层速查

同类浏览器 Agent 产品通常按下面的顺序长出来，可用来判断当前该补哪一层：

1. 读取页面与选中内容
2. 在多个标签页之间定位目标
3. 有界工具循环与可见的执行步骤
4. 执行前授权与主动提问
5. 写操作（点击、填写、滚动）
6. 上下文压缩、会话持久化
7. Skill、MCP、跨会话记忆

越靠后，对信任和调试能力的要求越高。
